# Публикация GitHub Pages и общий Gemini-наставник

Схема состоит из двух частей: GitHub Pages отдаёт статический сайт, а Cloudflare Worker выступает серверным посредником для Gemini. Gemini API key хранится только в Cloudflare Secret. Файл `ai-config.json` содержит публичный адрес Worker — это не секрет.

## Это бесплатно?

Не обязательно полностью:

- GitHub Pages обычно бесплатен для публичного репозитория и статического сайта, но действуют ограничения GitHub и выбранного плана.
- Cloudflare Worker можно запускать в пределах бесплатного плана/лимитов; лимиты и условия могут меняться.
- У Gemini API могут быть бесплатная квота и ограничения скорости, но доступность зависит от модели, проекта, региона и актуальных условий Google. При платном использовании может возникнуть расход.

Перед публикацией проверьте актуальные условия и лимиты в Google AI Studio/Google Cloud и Cloudflare. Задайте ограничения API и уведомления о расходах, если они доступны. Уведомление о бюджете само по себе может не остановить запросы. Worker открыт для посетителей сайта: предусмотренный лимит — базовая защита демонстрации, а не гарантия от злоупотреблений. Не отправляйте через демонстрационный наставник персональные или конфиденциальные данные учеников.

## 1. Получить новый Gemini API key

Ключ, ранее отправленный в переписке, следует считать раскрытым — сначала отзовите его.

1. Откройте [Google AI Studio — API keys](https://aistudio.google.com/apikey) и войдите в Google-аккаунт.
2. Удалите старый ключ в списке. Если его там нет, проверьте Google Cloud Console → **APIs & Services → Credentials**.
3. В AI Studio нажмите **Create API key**. Выберите существующий Google Cloud project или создайте новый и подтвердите создание ключа.
4. Скопируйте новый ключ. Храните его временно в менеджере паролей или сразу переходите к шагу 3 ниже. Не отправляйте ключ в чат, не помещайте в HTML, `ai-config.json`, GitHub Secrets или коммиты.
5. В Google Cloud Console → **APIs & Services → Credentials** выберите ключ и, если настройка доступна, ограничьте его API **Generative Language API**. Не задавайте HTTP referrer restriction: запрос к Gemini делает Worker, не браузер.
6. Проверьте квоты и настройки тарификации проекта. Учтите, что бюджетные уведомления не всегда автоматически блокируют дальнейшие запросы.

## 2. Развернуть Cloudflare Worker

Понадобятся аккаунт Cloudflare, Node.js с npm и терминал. Команды выполняйте из корня репозитория — той папки, где лежит `wrangler.toml`.

1. Авторизуйте Wrangler в Cloudflare:
   ```sh
   npx wrangler@latest login
   ```
   Откроется страница входа/подтверждения Cloudflare.
2. Разверните Worker без ключа:
   ```sh
   npx wrangler@latest deploy
   ```
   В конце Wrangler покажет адрес примерно такого вида:
   `https://statpracticum-ai.<ваш-subdomain>.workers.dev`
3. Добавьте Gemini key как секрет Worker:
   ```sh
   npx wrangler@latest secret put GEMINI_API_KEY
   ```
   Когда терминал попросит значение, вставьте новый ключ в этот интерактивный запрос. Не дописывайте сам ключ к команде и не помещайте его в файл. Wrangler отправит Secret в Cloudflare и обновит Worker.
4. В `ai-config.json` укажите выданный адрес Worker:
   ```json
   {
     "apiBase": "https://statpracticum-ai.<ваш-subdomain>.workers.dev"
   }
   ```
   Замените `<ваш-subdomain>` на настоящий адрес. Не добавляйте к URL `/api/ai` или завершающий слэш. URL публичный, ключа в нём нет.
5. В `wrangler.toml` уже разрешён origin `https://projectaaj2025-sys.github.io`. Если фактический адрес Pages отличается, замените значение `ALLOWED_ORIGINS` на origin сайта (только схема и домен, без `/StatPracticum/`) и снова выполните `npx wrangler@latest deploy`.

Для сайта настроена модель `gemini-flash-lite-latest` — та же, что указана в настройках Gemini. Если Worker создавался через Cloudflare Dashboard, добавьте в **Production → Variables and Secrets** обычную переменную `GEMINI_MODEL` со значением `gemini-flash-lite-latest` (Secret выключен), чтобы браузер и Worker использовали одну модель.

## 3. Опубликовать сайт на GitHub Pages

Для публикации из ветки `main` в корне репозитория есть `index.html`: он перенаправляет посетителя на `СтатПрактикум.html`. Поэтому в **Settings → Pages → Build and deployment** оставьте **Deploy from a branch**, выберите ветку `main` и папку `/(root)`, затем нажмите **Save**. После слияния изменений Pages автоматически обновит сайт. Сам архив `.7z` GitHub Pages не распаковывает; извлечённый `СтатПрактикум.html` должен быть в репозитории.

Адрес проекта: `https://projectaaj2025-sys.github.io/StatPracticum/`.

## 4. Включить и проверить ИИ-наставника

1. На опубликованном сайте откройте раздел ИИ-наставника. Если у браузера сохранились прежние настройки ИИ, откройте настройки наставника и выберите провайдера **Google AI Studio (Gemini)**.
2. После успешного обнаружения Worker появится выбор источника ключа. Выберите **Ключ сайта · Gemini** — ключ вводить в браузер не нужно. Если Worker не обнаружен, проверьте, что адрес в `ai-config.json` верный и сайт уже опубликован после изменения файла.
3. Включите внешнюю модель, если она выключена, сохраните настройки и нажмите **Проверить соединение**.
4. Если проверка не проходит, проверьте: в Cloudflare у Worker задан Secret `GEMINI_API_KEY`; адрес Worker совпадает с `ai-config.json`; `ALLOWED_ORIGINS` совпадает с доменом GitHub Pages; у Google key разрешён Generative Language API и не исчерпана квота.

После этого опубликованный Pages-сайт может обращаться к Gemini через Worker на разных устройствах. Сам ключ не скачивается с сайта и не переносится в офлайн-копию. В локальном HTML/офлайн-копии остаётся локальный ИИ-режим или личный ключ конкретного пользователя.
